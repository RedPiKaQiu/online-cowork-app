## Context

阶段 1 已将项目数据迁移至远程 PostgreSQL，并建立了 `projects.access_token_hash` 与软删除字段。当前应用仍为公开的单页 Demo。参见 proposal.md 的变更动机及已归档的数据库基础规格。

## Goals / Non-Goals

**Goals:**

- 用最少的运维组件实现可靠的单管理员认证和项目管理后台。
- 让项目访问令牌生成、哈希、展示和重置具备明确的安全边界。
- 将管理员保护置于服务端页面和 API 层，便于后续项目链接协作页复用。

**Non-Goals:**

- 不创建管理员用户表、注册、找回密码或多角色权限系统。
- 不实现匿名项目看板页面、任务 API、成员 API 或实时同步。
- 不让管理员后台直接展示或重新读取原始项目令牌。

## Decisions

### 环境配置的单管理员与加密校验

管理员邮箱和密码哈希由 `ADMIN_EMAIL`、`ADMIN_PASSWORD_HASH` 提供，不在数据库保存管理员身份。密码使用 Node.js `scrypt` 格式化哈希并以恒定时间比较验证；提供生成哈希的开发命令。该选择避免引入账号表和认证 SaaS，同时避免存储明文密码。后续需要多管理员时再迁移到账户表或专用认证提供商。

### 有时效、签名的 Cookie 会话

登录成功后服务端签发包含管理员标识与过期时间的 HMAC 签名会话 Cookie。会话由 `SESSION_SECRET` 验证，不写入数据库。Cookie 使用 `HttpOnly`、`SameSite=Lax`，生产环境使用 `Secure` 和根路径。相比数据库会话，单管理员部署更轻；相比仅在客户端存储标记，服务端可验证且不能被脚本读取。

### 后台路由与 API 边界

页面位于 `/login`、`/admin/projects` 和 `/admin/projects/[id]/settings`。所有 `/api/admin/*` Route Handler 先调用统一 `requireAdmin`；页面在服务端重定向未登录请求。页面使用 Server Actions 或同源 API 均可，但项目写操作必须统一经过授权、输入校验及数据库更新模块。

### 项目令牌的不可恢复存储

新建和重置时以加密安全随机数生成至少 32 字节令牌，以 `token + PROJECT_TOKEN_PEPPER` 计算 SHA-256 哈希并写入 `access_token_hash`。原 token 只在这一次响应中用于构造 `${APP_URL}/p/${token}`。管理员列表和后续 API 均不返回哈希。重置链接通过替换哈希立即使旧 token 无效。

### 项目删除与并发

删除仅设置 `deleted_at`，并在所有项目后台查询中排除已删除数据。编辑及删除请求应带项目当前版本或更新时间进行乐观并发检查；检测到陈旧版本时返回冲突信息，避免管理员标签页间无提示覆盖。

### 基础滥用防护

登录接口采用同源请求、通用错误响应与每 IP 的短时失败次数限制。项目写接口依赖 `SameSite=Lax` Cookie，并校验请求来源；若部署在多实例环境，速率限制应迁移至共享存储或反向代理。

## Risks / Trade-offs

- [环境变量泄露导致管理员接管] → 使用服务器机密文件权限、长随机 `SESSION_SECRET`、密码哈希及日志脱敏；更换密钥将使既有会话失效。
- [内存速率限制在重启后丢失] → 单服务器首期可接受；多实例或公网负载增加时使用反向代理或共享速率限制。
- [管理员丢失密码] → 首期通过重新生成服务器密码哈希恢复，不实现自助找回流程。
- [令牌在浏览器历史或日志中泄露] → 仅创建/重置时显示一次，提供重置链接；后续匿名项目页不得记录完整 URL token。
- [局域网开发使用 HTTP] → Cookie 的 `Secure` 属性仅在生产 HTTPS 生效；生产部署必须经 HTTPS 反向代理。

## Migration Plan

1. 添加所需环境变量与加密、会话、鉴权模块，并为其编写单元测试。
2. 添加管理员登录页、受保护后台路由与管理员项目 API。
3. 使用已有数据库表执行管理员项目 CRUD 与令牌重置，不新增数据库表或迁移。
4. 在远程开发数据库执行集成验证；部署时写入生产机密并在 HTTPS 域名下验证 Cookie。
5. 回滚时下线 `/admin` 路由并轮换 `SESSION_SECRET`；项目数据及令牌哈希保持不变。
