## ADDED Requirements

### Requirement: 项目看板以受控快照刷新保持数据新鲜度
系统 SHALL 为有效 `/p/[token]` 项目页提供手动刷新入口，并在页面首次可见、重新获得浏览器焦点、从后台恢复可见时重新读取当前项目快照。页面持续可见时，系统 MUST 以不短于 60 秒的固定间隔刷新；页面隐藏时 MUST 停止定时刷新。刷新只可读取当前项目访问链接对应的快照，且不得新增实时连接、订阅或后台刷新任务。

#### Scenario: 协作者手动刷新项目
- **WHEN** 协作者在项目看板触发“刷新最新数据”
- **THEN** 系统读取当前项目快照，并以项目、成员和任务的最新持久化状态替换看板显示

#### Scenario: 切回项目页面后获取更新
- **WHEN** 协作者将已打开的项目页面从后台切回前台，或页面重新获得浏览器焦点
- **THEN** 系统重新读取该项目快照，使其他窗口已保存的变更在无需整页刷新时显示

#### Scenario: 可见页面定时刷新且后台停止
- **WHEN** 项目页面持续可见超过刷新间隔
- **THEN** 系统重新读取一次当前项目快照

#### Scenario: 隐藏页面不继续轮询
- **WHEN** 项目页面变为不可见
- **THEN** 系统停止后续定时快照读取，直到页面再次可见

### Requirement: 快照刷新不破坏进行中的操作并提供可恢复状态
系统 SHALL 将手动刷新、自动刷新及既有请求失败/版本冲突后的快照恢复汇聚为去重流程。系统 MUST 在相关本地写入进行中时避免以自动刷新覆盖乐观状态，并在写入完成后恢复最新快照；刷新失败时 MUST 展示可理解的错误及可重试入口，并保留最后一个可信看板状态。

#### Scenario: 自动刷新遇到进行中的写入
- **WHEN** 自动刷新触发时项目看板存在尚未完成的本地写入
- **THEN** 系统不覆盖该写入的乐观状态，并在写入完成后以最新快照恢复一致状态

#### Scenario: 快照刷新失败
- **WHEN** 手动或自动快照读取因网络或服务端错误失败
- **THEN** 系统保留最后一个可信看板状态，显示刷新失败提示，并允许协作者再次尝试刷新
