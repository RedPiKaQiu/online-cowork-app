## 当前上下文

阶段 3 已有令牌格式检查、令牌哈希查找、活动项目过滤及浏览器安全的快照 DTO；项目页面当前使用只读 `BoardClient`，而旧 `CoworkBoard` 仍以本地状态实现任务、成员和拖拽交互。项目、成员和任务表已具备项目外键、复合成员归属约束、任务版本与按列位置的索引。动机与行为合同见 proposal.md 和 `project-board-mutations` 规格。

## 目标与非目标

**目标：**

- 提供一组按访问令牌授权、项目范围隔离且可测试的服务端 mutation。
- 让任务状态、负责人和排序在事务内保持一致，并以明确的冲突响应保护拖拽写入。
- 复用快照 DTO 与项目访问安全边界，避免将数据库内部字段返回浏览器。

**非目标：**

- 不在本阶段把项目页 UI 改为调用这些接口，也不实现客户端乐观更新或失败回滚。
- 不发布实时事件、不引入订阅服务或跨浏览器同步。
- 不修改管理员授权模型、项目链接生成模型或数据库表结构。

## 设计决策

### 以共享的项目上下文解析作为所有 mutation 的入口

新增服务器专用访问函数：先验证令牌格式和哈希，再查询未软删除项目，返回最少的项目上下文。每个 mutation 从该上下文取得 `projectId`，而不是信任请求体中的项目 ID；成员和任务的更新、删除查询同时以实体 ID 与 `projectId` 为条件。

这复用读取阶段的安全模型，且能令跨项目 ID 与不存在 ID 获得相同结果。替代方案是在每个路由自行查询令牌，容易造成过滤条件遗漏；在客户端携带 project ID 则不能构成授权边界。

### 路由轻量化，领域服务集中验证和事务

路由负责读取受尺寸限制的 JSON、转换路径参数与 HTTP 响应；服务器专用 mutation 服务负责字段规范化、业务验证、Drizzle 查询和浏览器安全 DTO 映射。定义可识别的错误类别（项目不可用、实体不存在、验证失败、版本冲突），由公共响应工具映射为统一 HTTP 状态及消息。

替代方案是让每个 Route Handler 直接写 SQL，短期文件更少但会使 token 隔离、字段限制和错误语义难以一致。无需在此阶段引入完整 schema-validation 库：已有依赖中不存在该库，使用小型显式解析器即可保持包范围不变。

### 成员调色板由服务端决定

成员创建使用现有 `MEMBER_COLORS` 等价的共享受支持调色板，并按当前项目色彩使用次数选择最少使用的颜色；更新成员名称不允许任意客户端颜色覆盖。服务端返回保存后的颜色与前景色。

这使同一项目的所有客户端看到一致的成员视觉标识，且避免将不受支持 CSS 值写入数据库。替代方案是接受客户端颜色并只做格式校验，会造成不同客户端的颜色选择策略不一致。

### 排序请求按意图执行并在事务内重排受影响列

`POST /tasks/reorder` 接收 `{ taskId, fromStatus, toStatus, targetIndex, expectedVersion, mutationId }`。事务中锁定/读取当前任务，校验项目、来源状态和版本；从来源列移除任务，插入目标列指定索引，然后将一列或两列的 `position` 重写为连续整数。移动到 `box` 时同时清空 `assigneeId`，并令被移动任务版本加一。返回任务和受影响列的排序信息，便于阶段 5 直接合并或冲突后重取快照。

首期按整列重排与实施指南的小数据量假设一致，避免分数索引和精度维护。替代方案是只更新移动任务的位置，无法稳定处理密集排序与并发插入；使用分数索引可减少写放大，但超出本阶段复杂度。

### 版本控制仅保护可冲突的任务变更

普通任务 PATCH 接受当前 `expectedVersion`，重排也必须提供它；数据库更新以 ID、项目 ID 和版本为条件或在事务读取后校验。冲突返回可区分的冲突状态，调用端在阶段 5 重新请求快照。项目版本会在项目元数据变更时递增，但不试图作为整块看板的全局锁。

这避免陈旧编辑与拖拽静默覆盖，同时不把成员新增等低冲突动作变成整项目串行写入。替代方案是 last-write-wins，较易实现但会导致拖拽与编辑丢失更新。

### 写后返回实体 DTO；实时事件延后

所有成功接口返回与项目快照兼容的项目、成员或任务 DTO，重排额外返回顺序需要的任务集合。事务提交成功后才可发布事件，但本阶段不接入发布器；阶段 6 在相同服务边界添加提交后事件发布。

这保持阶段间界面清晰。替代方案是现在引入空的实时抽象，会增加未被使用的基础设施和测试负担。

## 风险与权衡

- [整列重排产生多行写入] → 首期任务量较小；事务仅更新来源和目标两列，后续可迁移到分数索引。
- [无 UI 接入时接口难以获得完整端到端覆盖] → 为服务和路由建立项目隔离、取消分配、状态迁移、排序与冲突测试；阶段 5 再增加界面行为覆盖。
- [多人同时移动同一任务] → 以 `expectedVersion` 拒绝陈旧请求；客户端在后续阶段回滚或重新获取快照。
- [令牌出现在 URL] → 令牌仅用于解析项目上下文，禁止将其放入日志、响应体或错误文本；沿用哈希存储。

## 迁移方案

1. 添加共享输入解析、项目上下文和 mutation 服务及单元测试。
2. 添加项目、成员、任务和重排路由及集成测试。
3. 在预览环境使用新链接和数据库验证所有写入仍受项目隔离保护。
4. 本变更不改变 schema 或既有读取接口，可直接回滚应用版本；已写入的项目数据保持与现有表兼容。
