## Purpose

让持有有效项目访问链接的协作者能够安全地持久化项目、成员和任务变更，同时确保任何请求都不能越过其链接所属的项目边界。

## ADDED Requirements

### Requirement: 写入操作由有效项目访问链接授权并隔离
系统 SHALL 在每个项目写接口中从 URL 访问令牌解析活动项目，并将全部成员和任务查询及写入限制在该项目范围内。系统 MUST 将未知、失效或已删除项目的令牌视为不存在，且不得根据请求中的项目、成员或任务 ID 泄露其他项目的存在或数据。

#### Scenario: 有效链接写入自身项目
- **WHEN** 协作者以有效项目访问令牌提交该项目的合法变更
- **THEN** 系统仅修改该令牌所属项目的数据并返回成功结果

#### Scenario: 跨项目实体 ID 被拒绝
- **WHEN** 协作者以项目 A 的访问令牌请求修改项目 B 的成员或任务 ID
- **THEN** 系统不修改任何数据并返回与项目内不存在该实体一致的结果

#### Scenario: 失效链接无法写入
- **WHEN** 协作者以未知、已重置或属于已删除项目的访问令牌提交写请求
- **THEN** 系统返回统一的项目不可用结果且不执行写入

### Requirement: 项目元数据可被持久化更新
系统 SHALL 允许持有有效项目访问链接的协作者更新该项目的名称和描述。系统 MUST 校验名称为非空且不超过项目名称允许的长度，并在成功更新后返回浏览器安全的项目元数据及递增后的项目版本。

#### Scenario: 更新名称和描述
- **WHEN** 协作者提交合法的非空名称和描述
- **THEN** 系统持久化新的名称和描述并返回更新后的项目快照字段

#### Scenario: 无效项目名称被拒绝
- **WHEN** 协作者提交空白或超长项目名称
- **THEN** 系统返回可理解的验证错误且保留原有项目数据

### Requirement: 成员在项目范围内管理
系统 SHALL 允许协作者在其项目中创建、更新和删除成员；成员名称 MUST 为非空且受长度限制，成员颜色和前景色 MUST 由服务端生成或校验为受支持值。删除成员时，系统 MUST 在同一事务中将该项目所有分配给该成员的任务取消分配，然后删除成员。

#### Scenario: 创建和更新成员
- **WHEN** 协作者为有效项目提交合法的成员名称或成员编辑内容
- **THEN** 系统持久化该项目成员并返回其浏览器安全字段

#### Scenario: 删除成员会取消项目任务分配
- **WHEN** 协作者删除项目中的成员
- **THEN** 系统在删除成员后使该项目原先分配给此成员的全部任务 `assigneeId` 变为 `null`

#### Scenario: 无法删除其他项目成员
- **WHEN** 协作者使用当前项目链接删除不属于该项目的成员 ID
- **THEN** 系统不删除成员、不改变任何任务分配并返回实体不存在结果

### Requirement: 任务写入遵守看板领域规则
系统 SHALL 允许协作者在其项目中创建、编辑和删除任务，并修改其标题、描述、负责人和状态。任务标题 MUST 为非空且受长度限制；负责人 MUST 是同一项目内的现有成员或为空；任务进入 `box` 状态时，系统 MUST 强制清空负责人。成功创建、修改或删除任务后，系统 MUST 返回足以更新看板的浏览器安全结果。

#### Scenario: 创建任务
- **WHEN** 协作者提交合法标题和目标状态以创建任务
- **THEN** 系统在该项目目标列末尾持久化未分配任务并返回新任务

#### Scenario: 修改任务及负责人
- **WHEN** 协作者为项目内任务提交合法的标题、描述、状态或同项目负责人
- **THEN** 系统持久化变更并返回递增版本的任务

#### Scenario: 任务移入事项盒子时取消分配
- **WHEN** 协作者将带负责人的任务移入 `box`
- **THEN** 系统持久化 `box` 状态且任务负责人为空

#### Scenario: 跨项目负责人被拒绝
- **WHEN** 协作者为任务指定属于另一项目的成员 ID
- **THEN** 系统返回验证或实体不存在结果且不修改任务

### Requirement: 任务排序表达明确意图并处理并发
系统 SHALL 提供任务重排操作，接收任务 ID、来源状态、目标状态、目标索引、预期任务版本和客户端 mutation ID。系统 MUST 在单一事务中验证任务属于当前项目、来源状态和预期版本，按目标索引重算受影响列的位置，必要时将移入 `box` 的任务取消分配，并递增任务版本。版本或来源状态不匹配时，系统 MUST 拒绝该请求且不得留下部分排序变更。

#### Scenario: 列内重排任务
- **WHEN** 协作者以当前版本将任务移动到同一列的合法目标索引
- **THEN** 系统按请求后的顺序持久化该列任务，并返回更新后的任务或看板排序结果

#### Scenario: 跨列移动任务
- **WHEN** 协作者以当前版本将任务从一个状态移动到另一个状态的合法目标索引
- **THEN** 系统持久化两个受影响列的连续顺序和任务的新状态

#### Scenario: 陈旧拖拽请求不覆盖新变更
- **WHEN** 重排请求的预期版本与服务器中的任务版本不一致，或其来源状态已改变
- **THEN** 系统返回冲突结果且不修改任务状态、负责人或任一列的顺序

#### Scenario: 不合法排序负载被拒绝
- **WHEN** 重排请求缺少有效 mutation ID、包含不支持的状态或目标索引为负数
- **THEN** 系统返回验证错误且不修改看板

### Requirement: 写接口返回一致且安全的失败结果
系统 SHALL 对格式错误的请求体、无效字段和不满足领域规则的写请求返回一致、可供界面展示的客户端错误。系统 MUST 限制请求体大小，并且响应、日志和错误信息不得包含原始项目访问令牌或访问令牌哈希。

#### Scenario: 格式错误的写入请求
- **WHEN** 客户端向项目写接口提交非 JSON、超出允许大小或字段类型错误的请求体
- **THEN** 系统不执行写入并返回客户端可处理的错误结果
