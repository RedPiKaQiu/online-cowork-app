## Context

参见 [proposal.md](./proposal.md) 的变更动机。正式项目页由 `BoardClient` 的纵向 flex 布局、一个响应式 grid 工作区、两个 `TaskColumn` 和底部 `QuickAddBar` 组成。`TaskColumn` 的任务容器已经声明 `overflow-y-auto`，但桌面端根容器只有最小高度，工作区也保留了 flex/grid item 的自动最小尺寸，因此任务内容会扩大祖先，而不是在列内产生 overflow。

静态 Demo 已采用“桌面端固定视口、移动端自然页面流”的布局，可作为一致性参考。实现必须继续支持动态错误提示占用顶部栏与看板之间的空间，并避免改变任务拖拽、完成状态和持久化流程。

## Goals / Non-Goals

**Goals:**

- 建立从桌面端动态视口到任务滚动容器的完整受限高度链。
- 让两个活动任务列分别保存和控制自己的滚动位置。
- 在窄屏设备上保留可理解的上下文和足够的单列操作空间。
- 让滚动区域能被辅助技术识别，也能由键盘用户直接操作。
- 以真实浏览器的几何尺寸和滚动状态验证布局，而不是依赖静态 markup 测试。

**Non-Goals:**

- 不改变已完成事项抽屉；它已经由固定高度面板和内部 `overflow-y-auto` 构成独立滚动区域。
- 不引入虚拟列表、分页或任务数量上限。
- 不调整任务排序协议、服务端 API、状态管理或数据模型。
- 不将移动端看板改为标签页或横向轮播。
- 不定制跨浏览器滚动条外观；滚动条是否常驻显示继续遵循操作系统设置。

## Decisions

### 1. 桌面端使用固定动态视口，移动端保留自然文档流

在现有双列断点上，`BoardClient` 使用 `h-dvh` 和 `overflow-hidden`，顶部栏、状态提示和快速添加栏不参与压缩；`main` 使用 `min-h-0` 接收剩余高度。grid 的单行轨道显式使用 `minmax(0, 1fr)`，避免内容的固有最小高度反向撑开工作区。

在窄屏断点下，根容器继续使用 `min-h-dvh` 而不锁定高度，两个列保持纵向排列。每列设置可用的最小高度和基于 `dvh` 的最大高度，页面负责在两列之间移动，列内部负责浏览长列表。快速添加栏在窄屏下固定于页面底部附近，并在需要时换行，确保输入入口不会因长列表难以到达。

未采用“所有尺寸都固定为一个视口”，因为这会在移动端把两个纵向排列的列压缩为两个过小区域。也未采用移动端标签页，因为它会引入新的导航状态和隐藏列语义，超出本次布局修复范围。

### 2. 任务列分离固定框架与唯一滚动主体

`TaskColumn` 外层负责边框、圆角和裁剪，并使用 `min-h-0 overflow-hidden`。列标题使用 `shrink-0`，任务容器作为唯一滚动主体使用 `min-h-0 flex-1 overflow-y-auto`。桌面端为任务容器增加滚动链约束，使到达边界后的继续滚动不传播到页面；可使用稳定的 scrollbar gutter 减少滚动条出现时的宽度变化。

不把滚动设置放在整个 `TaskColumn` 上，因为那会让列标题随任务一起滚走，也会削弱用户对当前列的定位。

### 3. 滚动区域采用命名 region 和显式键盘焦点

每个任务容器暴露与可见列标题关联的 accessible name，并允许通过 Tab 获得焦点；`focus-visible` 样式应与项目现有 ring token 一致。键盘聚焦后，浏览器原生的方向键、Page Up、Page Down、Home 和 End 行为用于浏览列表，不引入自定义按键处理。

选择原生 overflow 滚动，是因为它保留触控惯性、辅助技术兼容性和较低维护成本。不会以隐藏滚动条作为视觉优化。

### 4. 使用 Playwright 验证可观察的滚动行为

新增包含足够多 `box` 和 `todo` 事项的测试数据，通过桌面与窄屏 viewport 验证：任务容器的 `scrollHeight` 大于 `clientHeight`、两列 `scrollTop` 相互独立、固定区域保持在视口中，以及移动端文档可以访问两个受限高度的列。

现有组件 SSR 测试继续承担基础内容渲染检查。布局不使用 class 字符串作为主要断言，因为 class 存在不代表浏览器最终形成了可滚动高度。

## Risks / Trade-offs

- [移动端同时存在页面滚动和列内滚动，可能产生嵌套滚动感] → 仅在内容实际溢出时启用列滚动，保持列高度足够大，并只在桌面端阻断滚动链。
- [桌面端新增错误提示时，可用看板高度会缩小] → 将提示作为不可压缩的 flex item，由 `main` 自动取得剩余空间；在低高度 viewport 中加入回归用例。
- [macOS 默认使用覆盖式滚动条，用户可能看不到常驻轨道] → 以可滚动性和稳定 gutter 为标准，不依赖强制绘制自定义滚动条。
- [overflow 容器可能改变长列表拖拽时的边缘自动滚动行为] → 在浏览器测试中覆盖靠近上下边缘的拖拽；若原生 HTML Drag and Drop 无法可靠滚动，再在实现阶段增加局部边缘滚动处理，不改变 API。
- [移动端 sticky 快速添加栏可能受软键盘和 safe area 影响] → 使用动态视口单位并验证聚焦输入框后的可见性；保留自然文档流作为回退。

## Migration Plan

1. 先调整响应式高度链和任务列滚动主体，不改业务状态或数据接口。
2. 补充滚动区域的可访问语义和聚焦样式。
3. 添加桌面及窄屏 Playwright 场景，并验证长列表拖拽、错误提示和输入框聚焦。
4. 发布不需要数据迁移；若出现布局回归，可单独回退相关响应式 class 和测试，不影响持久化数据。
