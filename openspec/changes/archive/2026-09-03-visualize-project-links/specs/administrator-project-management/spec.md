## MODIFIED Requirements

### Requirement: 管理员项目列表
系统 SHALL 向已认证管理员展示全部活动项目的名称、描述、创建时间、更新时间及项目操作入口，并为具有可恢复访问凭据的项目展示完整项目访问 URL、复制操作和直接访问入口。对于既有但无法恢复原始访问凭据的项目，系统 MUST 显示链接不可用状态及重置链接入口，而不得伪造或自动替换链接。软删除项目 MUST 默认不显示在活动列表中；列表响应 MUST 不包含项目访问令牌哈希、密文或其他内部凭据字段。

#### Scenario: 管理员查看具有可用链接的项目列表
- **WHEN** 已认证管理员打开项目管理后台，且活动项目具有可恢复的当前访问凭据
- **THEN** 系统在对应项目条目中显示指向该项目的完整访问 URL、复制操作和直接访问入口

#### Scenario: 管理员复制项目链接
- **WHEN** 管理员对具有可用链接的项目执行复制操作
- **THEN** 系统将该项目的完整访问 URL 写入剪贴板，并显示复制成功反馈

#### Scenario: 项目链接复制失败
- **WHEN** 浏览器拒绝或无法完成剪贴板写入
- **THEN** 系统保留可选择的完整访问 URL，并显示复制失败反馈

#### Scenario: 管理员直接打开所选项目
- **WHEN** 管理员点击某个项目条目中的访问链接
- **THEN** 浏览器导航至该链接所标识的项目页面，而不是其他项目页面

#### Scenario: 既有项目缺少可恢复链接
- **WHEN** 已认证管理员查看迁移前创建且尚未重置链接的活动项目
- **THEN** 系统显示链接不可用状态和重置入口，不显示无效 URL，也不自动使该项目的当前链接失效

#### Scenario: 管理员查看项目列表的安全边界
- **WHEN** 已认证管理员打开项目管理后台
- **THEN** 系统显示活动项目列表，且页面和列表响应均不泄露访问令牌哈希、令牌密文或加密密钥

### Requirement: 创建项目
系统 SHALL 允许已认证管理员创建名称必填的项目，并为项目生成新的不可预测访问令牌。系统 MUST 持久化令牌哈希用于项目访问验证，并以服务器端加密保护可恢复的原始令牌，使其仅能通过已认证管理员界面或管理员 API 作为项目访问 URL 使用；系统 MUST NOT 持久化明文令牌。

#### Scenario: 管理员创建有效项目
- **WHEN** 管理员提交有效项目名称
- **THEN** 系统保存新项目，并在创建结果及后续活动项目列表中提供该项目的可复制访问 URL

#### Scenario: 管理员提交空白项目名称
- **WHEN** 管理员提交空白项目名称
- **THEN** 系统拒绝创建并显示验证错误

#### Scenario: 非管理员无法恢复项目链接
- **WHEN** 未认证请求读取活动项目列表或尝试恢复项目访问 URL
- **THEN** 系统拒绝请求，且不返回原始令牌、完整访问 URL、令牌哈希或令牌密文

### Requirement: 重置项目访问链接
系统 SHALL 允许已认证管理员重置项目访问链接。重置后旧令牌 MUST 立即失效，新令牌 MUST 以哈希形式用于访问验证并以服务器端加密形式支持管理员后续恢复；系统 MUST 在重置响应及后续活动项目列表中提供新的项目访问 URL，且不得持久化明文令牌。

#### Scenario: 管理员重置访问链接
- **WHEN** 管理员确认重置活动项目的访问链接
- **THEN** 系统替换已保存的令牌哈希和密文，并显示新的可复制 URL

#### Scenario: 管理员在重置后再次查看列表
- **WHEN** 管理员重置链接后重新打开项目管理后台
- **THEN** 系统在对应项目条目中显示重置后生成的当前项目访问 URL

#### Scenario: 旧链接失效
- **WHEN** 链接重置后使用原令牌验证项目访问
- **THEN** 系统不会将该令牌识别为有效项目凭据
