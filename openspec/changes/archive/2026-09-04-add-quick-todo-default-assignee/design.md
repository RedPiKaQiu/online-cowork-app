## Context

参见 [proposal.md](./proposal.md) 的变更动机。当前 `QuickAddBar` 自己维护标题和目标列，只向 `BoardClient` 提交 `{ title, status }`；`BoardClient` 的乐观任务和 `projectBoardApi.createTask` 也固定不带负责人，服务端 `createTaskByToken` 最终将 `assigneeId` 写为 `null`。项目快照已经包含完整成员列表，任务更新接口已有同项目负责人校验，因此不需要新增数据模型。

快速添加栏位于固定的页面底部区域，桌面端以单行排列，窄屏下允许换行。新增选择器必须避免挤压标题输入与添加按钮。另一个约束是创建失败后需要保留草稿，而当前快速栏在调用同步 `onAdd` 后立即清空标题，不能感知服务端结果。

## Goals / Non-Goals

**Goals:**

- 让一次快速创建请求同时表达目标状态和可选负责人，并使乐观状态与最终响应一致。
- 让负责人默认值只存在于当前 `QuickAddBar` 实例，成员列表变化时可自动失效。
- 让提交方获得明确的成功或失败结果，以正确决定清空还是保留草稿。
- 在现有桌面端固定底栏和窄屏 sticky 布局中提供稳定、可访问的负责人选择体验。

**Non-Goals:**

- 不提供项目级或账号级永久默认负责人，也不使用 `localStorage`、cookie 或服务端字段跨页面会话保存选择。
- 不推断“当前用户”；项目协作页只有访问链接和成员列表，没有登录身份与成员身份映射。
- 不支持一次任务分配多个负责人，不改变事项盒子必须无负责人的领域规则。
- 不新增成员创建方式；选择器只链接到既有成员管理入口。

## Decisions

### 1. 默认负责人由快速添加栏维护为短生命周期 UI 状态

`QuickAddBar` 接收项目成员列表和打开成员管理界面的回调，并维护 `selectedAssigneeId: string | null`。初值始终为 `null`，成功创建后不重置。目标切换到 `box` 时只隐藏选择器并在提交参数中使用 `null`，不销毁已选值；切回 `todo` 时恢复仍然有效的值。

成员列表变化后，组件校验所选 ID 是否仍存在；若不存在则重置为 `null`。这样同时覆盖本窗口删除、快照刷新和其他窗口删除成员的情况。

选择本地组件状态而不是项目快照或持久化设置，是因为该值描述的是当前录入批次，而不是共享业务数据。相比跨会话记忆，它不会在共享设备或下一次访问时制造隐蔽的误分配。

### 2. 负责人选择器只在 `todo` 目标下呈现并持续暴露当前值

选择器使用紧凑触发按钮展示成员颜色、姓名或“未分配”，弹出列表包含所有当前项目成员和明确的“未分配”选项。项目没有成员时，弹层显示空状态与“管理成员”操作；打开成员管理时保留当前标题草稿。

触发按钮具有明确的负责人可访问名称和展开状态；弹层支持 Tab/方向键导航、Enter 或 Space 确认、Escape 关闭，并在关闭后将焦点返回触发按钮。选择后不自动提交任务，避免用户未输入或未确认标题时产生写入。

桌面端顺序为“目标列 → 负责人 → 标题 → 添加”。窄屏下第一行放置目标分段控件和受最大宽度约束的负责人按钮，第二行保留可伸缩标题输入与固定宽度添加按钮；长姓名在按钮内截断，并通过可访问名称保留完整信息。

在 `box` 目标下完全隐藏负责人，而不是显示禁用控件，因为负责人对事项盒子无意义。保留内部选择则降低用户临时切换目标后再次分配的成本。

### 3. 创建回调返回结果，快速栏仅在成功后清空标题

将 `QuickAddBar.onAdd` 调整为接收 `{ title, status, assigneeId }` 并返回可等待的成功结果。提交期间组件记录本次参数并进入进行中状态，避免用户修改同一草稿导致成功响应清空后来输入的内容。成功后清空标题、保留负责人并将焦点返回标题输入框；失败后保留标题和负责人，由现有全局错误区域说明失败原因并允许原样重试。

`BoardClient` 创建乐观任务时直接使用提交的有效负责人，并让创建 mutation 把成功或失败返回给快速栏。请求期间使用独立且真实生效的快速创建 pending 状态；任务的临时 ID 仍用于将服务端响应替换到正确位置。

相比提交后立即清空再在失败时恢复快照，这一方案不会丢失用户草稿，也不需要从错误状态反向重建标题。首版在单个创建完成前不接受下一次提交，以避免多个并发草稿的清空、错误归属与焦点管理复杂度。

### 4. `POST /api/projects/:token/tasks` 原子接受可选负责人

浏览器请求 DTO 扩展为 `{ title, status, assigneeId?: string | null }`。服务端在目标状态允许负责人时复用既有项目范围成员解析规则，在执行 `INSERT` 前确认非空 ID 属于当前项目；无效或跨项目 ID 返回客户端可处理的错误，并且不创建任务。`box` 状态无条件将最终 `assigneeId` 归一为 `null`。

负责人随任务在一次 `INSERT` 中保存并随创建 DTO 返回。相比创建后额外调用 `PATCH`，该方案不会短暂暴露未分配任务，不增加版本号，也避免第二次请求失败留下半完成状态。数据库既有的项目范围复合外键继续作为最终一致性保护。

### 5. 测试围绕状态边界和请求原子性分层覆盖

组件测试覆盖选择、沿用、目标切换、成员失效、无成员入口、提交成功/失败、键盘关闭和窄屏结构；`BoardClient`/API 客户端测试验证乐观负责人和请求负载；服务端 mutation 测试验证 `todo` 的同项目成员、空负责人、跨项目拒绝，以及 `box` 强制清空。页面级测试验证快速栏在桌面和窄屏下没有遮挡或水平溢出。

## Risks / Trade-offs

- [连续添加必须等待上一条请求完成，弱网下录入节奏会变慢] → 清晰显示“添加中…”并优先保证草稿和错误归属可靠；未来若有真实批量录入需求，再设计多请求队列。
- [成员在选择后、提交前或写入过程中被其他会话删除] → 提交前用最新成员属性校验，服务端再次做项目范围校验；失败时保留草稿、刷新快照并将失效选择重置为“未分配”。
- [增加控件后窄屏快速栏高度或宽度回归] → 使用明确的两行布局、截断姓名和固定提交按钮，并在软键盘出现时进行视口测试。
- [弹层靠近底部时超出视口或被 sticky 层裁剪] → 向上定位弹层，限制最大高度并允许内部滚动，保持层级高于快速栏内容。
- [“沿用”可能造成用户忘记当前分配] → 负责人始终在快速栏中可见，使用成员颜色和姓名强化反馈，并提供一键切回“未分配”。

## Migration Plan

1. 先扩展服务端创建逻辑与请求 DTO，使旧客户端省略 `assigneeId` 时继续创建未分配任务。
2. 再发布前端选择器、短生命周期状态和可等待的创建流程；无需迁移既有数据。
3. 若需回滚，可先回滚前端以停止发送负责人字段，再回滚服务端可选字段处理；数据库内容和 schema 均无需恢复。
