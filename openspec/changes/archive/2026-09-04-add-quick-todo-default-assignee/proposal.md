## Why

项目页快速添加“当前待办”时只能先创建未分配任务，再到任务卡片中单独指定负责人，连续录入同一成员的多条待办需要反复操作。快速添加栏应允许用户预先选择负责人并沿用于本次页面会话中的后续待办，同时保持分配意图始终可见且可撤销。

## What Changes

- 当快速添加目标为“当前待办”时，在快速添加栏显示负责人选择器，允许选择同项目成员或“未分配”。
- 选定的负责人作为当前页面会话内的快速添加默认值，成功创建后继续沿用；页面重新加载后恢复为“未分配”。
- 切换到“事项盒子”时隐藏负责人选择器并始终创建未分配任务；切回“当前待办”时恢复本页面此前的选择。
- 当所选成员被删除或不再存在于最新项目快照中时，自动恢复为“未分配”。没有项目成员时提供清晰空状态和成员管理入口。
- 创建失败时保留待提交标题和负责人选择，允许协作者直接重试。
- 扩展任务创建请求，使“当前待办”可在一次原子写入中携带同项目负责人；继续由服务端强制保证事项盒子任务无负责人。
- 快速添加栏在桌面端和窄屏下保持标题输入与提交操作可用，并为负责人选择提供完整键盘交互和可访问名称。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `interactive-project-board`: 扩展快速创建交互，使当前待办可以选择并沿用页面会话内的默认负责人，同时覆盖响应式布局、成员空状态和键盘可用性。
- `project-board-mutations`: 扩展任务创建写入，使当前待办可原子保存可选的同项目负责人，并继续执行事项盒子取消分配及跨项目校验规则。

## Impact

- 前端主要影响 `QuickAddBar`、`BoardClient`、负责人选择 UI 及其状态和测试。
- 浏览器 API 客户端和 `POST /api/projects/:token/tasks` 请求 DTO 增加可选 `assigneeId`。
- 服务端 `createTaskByToken` 增加负责人解析与项目范围校验，但不需要数据库 schema 迁移或新增依赖。
- 现有“创建任务始终未分配”的规格将调整为按目标状态决定是否接受负责人。
