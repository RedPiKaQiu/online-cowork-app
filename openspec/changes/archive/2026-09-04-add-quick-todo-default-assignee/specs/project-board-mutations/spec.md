## MODIFIED Requirements

### Requirement: 任务写入遵守看板领域规则
系统 SHALL 允许协作者在其项目中创建、编辑和删除任务，并修改其标题、描述、负责人和状态。任务标题 MUST 为非空且受长度限制；负责人 MUST 是同一项目内的现有成员或为空；创建或更新进入 `box` 状态的任务时，系统 MUST 强制清空负责人。创建任务时，系统 MUST 在同一次写入中保存目标状态允许的负责人。成功创建、修改或删除任务后，系统 MUST 返回足以更新看板的浏览器安全结果。

#### Scenario: 创建带负责人的当前待办
- **WHEN** 协作者提交合法标题、`todo` 目标状态和同项目负责人以创建任务
- **THEN** 系统在当前待办列末尾原子持久化任务及负责人并返回新任务

#### Scenario: 创建未分配的当前待办
- **WHEN** 协作者提交合法标题、`todo` 目标状态且负责人为空
- **THEN** 系统在当前待办列末尾持久化未分配任务并返回新任务

#### Scenario: 创建事项盒子任务时忽略负责人
- **WHEN** 协作者提交合法标题和 `box` 目标状态，并同时提交一个同项目负责人
- **THEN** 系统在事项盒子列末尾持久化负责人为空的任务并返回新任务

#### Scenario: 修改任务及负责人
- **WHEN** 协作者为项目内任务提交合法的标题、描述、状态或同项目负责人
- **THEN** 系统持久化变更并返回递增版本的任务

#### Scenario: 任务移入事项盒子时取消分配
- **WHEN** 协作者将带负责人的任务移入 `box`
- **THEN** 系统持久化 `box` 状态且任务负责人为空

#### Scenario: 跨项目负责人被拒绝
- **WHEN** 协作者在创建或修改允许分配负责人的任务时指定属于另一项目的成员 ID
- **THEN** 系统返回验证或实体不存在结果且不修改任务
