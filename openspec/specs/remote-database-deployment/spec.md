# remote-database-deployment Specification

## Purpose

定义远程 PostgreSQL 开发数据库的安全部署与访问行为，使没有本地 Docker 的开发环境能够通过受控通道使用持久化数据库，并为同机应用部署做好准备。

## Requirements

### Requirement: 远程数据库受信任网络暴露
系统 SHALL 将远程 PostgreSQL 服务限制为服务器本机、内部容器网络或明确受信任的局域网客户端；数据库端口 MUST NOT 直接暴露给公网，且局域网直连 MUST 由服务器防火墙限制为指定客户端 IP。

#### Scenario: 外部网络访问数据库端口
- **WHEN** 互联网主机尝试直接连接服务器的 PostgreSQL 默认端口
- **THEN** 连接无法建立

#### Scenario: 获授权的局域网客户端访问数据库
- **WHEN** 服务器本机进程、获授权的同一容器网络中的应用或防火墙白名单内的局域网客户端连接数据库
- **THEN** 数据库接受携带有效凭据的连接

### Requirement: 本地开发安全访问
系统 SHALL 支持开发者通过 SSH 隧道或防火墙白名单内的局域网 IP 访问远程开发数据库，并使用环境变量提供连接字符串。数据库凭据 MUST NOT 被提交到版本控制系统。

#### Scenario: 已授权网络路径的本地开发连接
- **WHEN** 开发者建立 SSH 隧道或从防火墙白名单内的局域网地址配置有效连接字符串
- **THEN** 本地开发应用可连接远程开发数据库

#### Scenario: 环境配置被提交检查
- **WHEN** 开发人员检查将要提交的配置文件
- **THEN** 仓库仅包含变量名模板，不包含数据库密码或真实连接字符串

### Requirement: 数据库持久化与可恢复性
系统 SHALL 将 PostgreSQL 数据存放在服务器持久化卷中，并提供创建与恢复数据库备份的文档化步骤。

#### Scenario: 数据库容器重建
- **WHEN** PostgreSQL 容器被停止并重新创建且持久化卷未删除
- **THEN** 已保存的项目、成员和任务数据仍可读取

#### Scenario: 从备份恢复
- **WHEN** 运维人员按部署文档将有效备份恢复到目标数据库
- **THEN** 备份生成时的持久化数据可被重新读取
